# 확장 기획안

clotho v1은 legacy가 하던 일을 전부 하고 그 이상은 하지 않는다. 이식이 목표였으니
그게 맞았다. 여기서부터는 다른 질문이다 — **무엇을 더 할 수 있는가.**

기획안 14건. 근거는 세 곳에서 나왔다.

1. **실데이터 383개 문서**의 사용 패턴 (`docs/RESEARCH.md`)
2. **에디터 커버리지 감사**가 드러낸 구멍 (`docs/AUDIT-EDITOR.md`)
3. **갤러리를 만들면서 실제로 불편했던 것** — 특히 P1

각 안에 **비용**과 **호환성**을 붙였다. 호환성이 "깨짐"인 안은 채택하지 않는 쪽으로
기울어야 한다. 383개 문서와 두 개의 소비 저장소가 이미 v1에 묶여 있다.

## P1 — 반복 트랙

**문제.** 형식에 반복이 없다. 8칸 배열을 훑는 커서 하나가 키프레임 16개다.
갤러리의 `iteration` 문서는 그래서 TypeScript로 생성해 썼다 — 손으로 쓸 만한 분량이
아니기 때문이다. 실데이터에서 키프레임 20개가 넘는 트랙이 반복 패턴인 경우가 많다.

**제안.** 트랙에 반복 지시를 붙인다.

```json
{
  "property": "x",
  "repeat": { "count": 8, "every": 420, "offset": 70 },
  "keyframes": [
    { "time": 0, "value": 26, "ease": "easeOut" },
    { "time": 300, "value": 26 }
  ]
}
```

`i`번째 회차는 키프레임 시각에 `i * every`를, 숫자 값에 `i * offset`을 더한다.
`count: "fill"`이면 `duration`까지 채운다.

**스키마 영향.** `propertyTrackSchema`에 선택 필드 하나. 없으면 지금과 동일.

**호환성.** 완전 하위호환. 런타임에서 키프레임을 펼쳐 계산하므로 스냅샷 코드는 안 바뀐다.

**비용.** 중. 펼치기 함수와 검증(펼친 결과가 `duration`을 넘는지) 정도.

**주의.** 이걸 넣으면 문서를 읽는 사람이 "실제 키프레임"을 머리로 계산해야 한다.
에디터가 펼친 모습을 보여주지 못하면 오히려 나빠진다. **에디터 지원과 함께 넣는다.**

## P2 — 요소 템플릿 / 인스턴싱

**문제.** P1이 시간축 반복이라면 이건 공간축 반복이다. 배열 8칸을 그리려면 `rect`를
8개 쓴다. 자료구조 시각화가 대부분 이 모양이고, 실데이터에서 `rect` 2,304개 중 상당수가
이런 반복이다.

**제안.** 정의를 한 번 쓰고 데이터로 펼친다.

```json
{
  "type": "each",
  "id": "cells",
  "over": [4, 9, 2, 7, 1, 8, 3, 6],
  "layout": { "direction": "row", "gap": 8 },
  "template": {
    "type": "rect",
    "id": "cell-$i",
    "x": 0, "y": 66, "width": 54, "height": 58,
    "label": "$value"
  }
}
```

`$i`와 `$value`만 치환한다. 표현식은 P3의 영역이고 여기서는 넣지 않는다.

**스키마 영향.** 새 요소 타입 하나 — 다만 렌더되는 타입이 아니라 **펼쳐지는 타입**이다.
스키마 계층이 아니라 그 앞 단계(전개기)에 두는 편이 깨끗하다.

**호환성.** 하위호환. 다만 `id`가 생성되므로 효과·연결선이 `cell-3`을 가리키는 것이
검증 가능해야 한다.

**비용.** 대. 전개기와 `id` 생성 규칙, 그리고 에디터가 펼친 것을 편집하려 할 때의
의미(원본을 고칠 것인가, 떼어낼 것인가)를 정해야 한다. 그 결정이 어려운 부분이다.

## P3 — 표현식 값

**문제.** 키프레임 값이 상수뿐이라, "다른 요소의 x + 20"을 표현할 수 없다. 지금은
같은 숫자를 두 곳에 쓰고 둘 다 고치는 수밖에 없다.

**제안.**

```json
{ "time": 1000, "value": { "expr": "el('box').x + 20" } }
```

**핵심 제약: 순수해야 한다.** 코어는 `Date`, `Math.random`, 호스트 전역에 손댈 수 없고,
`frame(t) = f(document, t)`가 깨지면 서버 렌더와 필름스트립이 전부 무너진다.
따라서 `eval`이 아니라 **작은 전용 문법**이어야 하고, 순환 참조를 정적으로 잡아야 한다.

**호환성.** 하위호환 (`value`가 union으로 넓어진다).

**비용.** 대. 파서, 평가기, 순환 검출, 에디터 입력 UI. **P1·P2보다 먼저 하면 안 된다** —
반복이 없는 상태에서 표현식만 생기면 쓸 데가 별로 없다.

## P4 — 경로 따라 이동

**문제.** 곡선 이동이 안 된다. `x`와 `y` 트랙을 각각 걸면 결과는 항상 직선 아니면
어색한 사각형 궤적이다. 실데이터에서 이동은 587개 arrow와 대부분의 rect 트랙에서
나타나는데 전부 직선이다.

**제안.** 트랙 대신 경로를 준다.

```json
"motion": {
  "path": "M 40 200 Q 200 40 360 200",
  "start": 500,
  "end": 2500,
  "ease": "easeInOut",
  "orient": "auto"
}
```

`orient: "auto"`면 진행 방향으로 회전한다 — 궤도를 도는 위성, 길을 따라가는 차량.

**스키마 영향.** 요소에 선택 필드 하나. `x`/`y` 트랙과 동시에 쓰면 경로가 이긴다(검증 경고).

**호환성.** 하위호환.

**비용.** 중. SVG의 `getPointAtLength`는 DOM API라 **코어에서 쓸 수 없다.** 순수한
경로 파서와 길이 계산을 직접 써야 한다. 여기가 이 안의 실제 비용이고, 직선·이차·삼차만
지원하면 감당할 만하다.

## P5 — `table` 요소

**문제.** 표를 그리려면 `rect`와 `text`를 격자로 깐다. 3×4 표가 요소 24개다. 배열,
행렬, 상태 전이표, 메모이제이션 표 — 알고리즘 시각화의 절반이 표다.

**제안.**

```json
{
  "type": "table",
  "id": "dp",
  "x": 40, "y": 60,
  "rows": 4, "cols": 5,
  "cellWidth": 56, "cellHeight": 40,
  "headers": ["", "a", "b", "c", "d"],
  "cells": [["", 0, 0, 0, 0], ["a", 0, 1, 1, 1]]
}
```

**셀 하나를 가리킬 수 있어야 한다.** `dp[1][2]`를 강조하는 게 이 요소를 만드는 이유의
대부분이므로, 효과와 트랙이 `"elementId": "dp", "cell": [1, 2]`를 받아야 한다.
그 접근 경로 설계가 이 안의 핵심이다.

**호환성.** 하위호환.

**비용.** 중. `rect`+`text`로 전개되므로 렌더는 새로 짤 게 없다. 셀 주소 지정이 일이다.

## P6 — `code` 요소 강화

**문제.** `code` 요소는 지금 **모노스페이스 글자가 든 상자**다. 문법 강조가 없고,
줄을 강조할 수 없고, 감사 결과 **에디터에서 만들 수조차 없다**(A1).
실데이터에서 19개 문서가 쓰는데 전부 손으로 JSON을 썼다.

**제안.** 세 가지를 얹는다.

1. **줄 강조.** `highlightLines: [3, 4]` — 시간에 따라 바뀌면 코드 워크스루가 된다.
   트랙 대상이므로 `interpolate: "discrete"`와 잘 맞는다.
2. **줄 단위 diff.** `+`/`-` 표시. before/after를 두 문서로 만들 필요가 없어진다.
3. **문법 강조.** 여기서 조심해야 한다 — 하이라이터는 크고, **코어는 순수해야 하며**,
   `language`가 자유 문자열이다. 코어에 넣지 말고 **토큰을 문서에 미리 구워 넣거나**
   호스트가 주입하는 형태여야 한다.

**호환성.** 1·2는 하위호환. 3은 형식이 아니라 파이프라인 결정이다.

**비용.** 중. 1이 가장 싸고 효용이 크다. **1만 먼저 해도 된다.**

**함께 할 것.** 에디터 A1 — 만들 수 없는 요소를 강화하는 것은 순서가 뒤바뀐 일이다.

## P7 — 스프링 / 커스텀 베지어 이징

**문제.** 이징이 4종뿐이다. `pop`이 튀는 느낌을 내지만 조절할 수 없다.

**제안.** `ease`를 문자열 대신 객체도 받게 한다.

```json
{ "time": 800, "value": 200, "ease": { "cubicBezier": [0.34, 1.56, 0.64, 1] } }
{ "time": 800, "value": 200, "ease": { "spring": { "stiffness": 180, "damping": 12 } } }
```

**스프링에는 함정이 있다.** 물리 스프링은 보통 상태를 적분해서 푸는데, 그러면
`frame(t) = f(document, t)`가 깨진다. **닫힌 형태 해**(감쇠 조화 진동자)를 써야 하고,
그건 `t`만으로 계산 가능하다. 이 제약을 지키면 문제없다.

**호환성.** 하위호환 (union 확장). 기존 4종 문자열 그대로 동작.

**비용.** 소. 큐빅 베지어 풀이는 20줄, 스프링 닫힌 해도 비슷하다.

**함께 할 것.** 에디터 A2 — `ease` 선택 UI 자체가 아직 없다. **UI 없이 종류만 늘리는
것은 의미가 없다.**

## P8 — 테마 토큰 색상

**문제.** 색이 문서에 하드코딩된다. `#e0e7ff`로 쓴 383개 문서는 다크 모드에서 그대로
밝다. 지금은 CSS 변수 매핑으로 무대 배경만 대응하고 **요소 색은 손대지 못한다.**

**제안.** 색 값이 토큰을 받게 한다.

```json
{ "fill": "@surface", "stroke": "@accent", "labelColor": "@fg" }
```

`@`로 시작하면 팔레트 조회, 아니면 리터럴. 팔레트는 문서에 기본값을 두고 호스트가 덮는다.

```json
"palette": {
  "light": { "surface": "#e0e7ff", "accent": "#6366f1" },
  "dark":  { "surface": "#1e1b4b", "accent": "#818cf8" }
}
```

**어려운 지점은 색 보간이다.** `color` 트랙이 `@accent`에서 `@danger`로 갈 때 언제
해석하는가. 보간 **전에** 해석해야 한다.

**호환성.** 하위호환. `@`로 시작하는 색은 지금 유효하지 않으므로 충돌이 없다.

**비용.** 중. 해석 지점(`resolveElementColor`)이 이미 한 곳이라 훅을 걸 자리는 있다.

**가치.** 실데이터 383개 전체가 라이트 모드 전제다. 마이그레이션 스크립트로 자주 쓰이는
색을 토큰으로 바꿔 줄 수 있다.

## P9 — 상호작용

**문제.** 애니메이션이 재생 전용이다. 클릭해서 다음으로, 호버해서 설명, 분기 선택이
전부 불가능하다.

**제안.**

```json
"interactions": [
  { "on": "click", "target": "next-btn", "action": { "seek": 2000 } },
  { "on": "hover", "target": "node-a", "show": ["tooltip-a"] }
]
```

**이건 형식의 성격을 바꾼다.** 지금 문서는 **시간의 함수**다. 상호작용을 넣으면 상태가
생기고, 서버 렌더·필름스트립·정적 내보내기가 전부 부분적으로만 의미를 갖게 된다.

**안전한 형태:** 상호작용을 **플레이어 조작으로만** 제한한다 — `seek`, `pause`, `speed`.
문서의 그림 자체를 바꾸지 않으면 순수성이 유지된다. 요소 표시/숨김까지 허용하면
그 선을 넘는다.

**호환성.** 하위호환이지만 어댑터마다 구현해야 한다.

**비용.** 대. 우선순위를 낮게 두는 이유는 비용보다 **성격 변화** 때문이다.

---

## P10 — 오디오 · 내레이션 트랙

**제안.** 문서에 오디오와 자막 큐를 붙인다.

```json
"audio": { "assetId": "narration", "offset": 0 },
"cues": [{ "time": 0, "text": "클라이언트가 SYN을 보냅니다" }]
```

**챕터 `subtitle`과 겹친다.** 이미 챕터에 자막이 있으므로, `cues`를 새로 만들기보다
**챕터를 세분화하는 것**이 맞을 수 있다. 오디오만 새로 필요한 부분이다.

**주의.** 오디오는 자동 재생이 막히고, `prefers-reduced-motion`과 별개로 소리 정책이
있으며, `assets`가 이미지 전용(`imageMimeSchema`)이라 넓혀야 한다.

**호환성.** 하위호환. **비용.** 중. **우선순위 낮음** — 블로그 임베드에서 소리는 대개
민폐다.

## P11 — 스프라이트 시트 / 비디오 내보내기

**문제.** 애니메이션을 공유할 방법이 링크뿐이다. README, 슬라이드, 소셜 미리보기에
넣을 수 없다.

**제안.** 이미 가능한 것의 마무리다. `renderDocumentToSvg(doc, t)`가 이미 프레임을
만들고 `examples/gallery/build.ts`가 이미 뽑는다. 남은 건 인코딩이다.

```
bunx clotho export doc.json --format gif --fps 24
bunx clotho export doc.json --format sprite --frames 60
```

**패키지 밖에 두는 것이 맞다.** GIF/MP4 인코더는 무겁고 플랫폼을 탄다. 코어는
**프레임을 주는 것까지**가 책임이고, `@shinkeonkim/clotho-export`가 받는다.
스프라이트 시트(SVG/PNG 격자)는 의존이 거의 없으니 CLI에 넣어도 된다.

**호환성.** 형식 변경 없음. **비용.** 중.

## P12 — 접근성 서술 트랙

**문제.** 스크린 리더에게 이 애니메이션은 **빈 그림**이다. `image.alt`가 v1에서
생겼지만 문서 전체를 설명하는 경로는 없고, `title`/`description`은 요약이지 서술이 아니다.

**제안.** 시각에 묶인 텍스트 서술.

```json
"narration": [
  { "time": 0,    "text": "클라이언트와 서버가 떨어져 있다" },
  { "time": 2000, "text": "클라이언트에서 서버로 SYN 화살표가 나타난다" }
]
```

어댑터가 이것을 `aria-live` 영역에 넣거나, 정적 대체 텍스트로 펼친다.
`prefers-reduced-motion`인 사람에게는 **애니메이션 대신 이 서술을 보여주는 것**이
지금의 "그냥 멈춤"보다 훨씬 낫다.

**호환성.** 하위호환.

**비용.** 소. 스키마 필드 하나와 어댑터당 몇 줄.

**우선순위가 높은 이유.** 싸고, 지금 완전히 비어 있고, 다른 안들과 충돌하지 않는다.
P10과 달리 자동 재생 정책 문제도 없다. **가장 먼저 해도 되는 안이다.**

## P13 — 문서 합성

**문제.** 긴 설명은 애니메이션 여러 개로 쪼개지고, 공통 배경(시스템 구성도 등)이
문서마다 복사된다.

**제안.**

```json
"include": [{ "document": "./base-topology.json", "at": 0, "as": "base" }]
```

**id 충돌·시간 오프셋·자산 병합**을 전부 정해야 하고, 순환 include를 막아야 한다.
로더가 비동기라 코어의 순수성 경계에 걸린다(문서를 가져오는 것은 호스트 일이다).

**호환성.** 하위호환. **비용.** 대. **우선순위 낮음** — P2(템플릿)가 중복의 상당 부분을
먼저 해결한다.

## P14 — 자동 레이아웃

**문제.** 좌표를 손으로 놓는다. 노드 12개짜리 그래프를 예쁘게 배치하는 데 대부분의
저작 시간이 든다. 감사에서 드러났듯 `path.d`는 편집 수단조차 없다.

**제안.** 배치를 계산으로 미룬다.

```json
{ "type": "group", "id": "graph", "layout": { "kind": "dag", "direction": "LR", "gap": 40 } }
```

자식의 `x`/`y`가 없으면 레이아웃이 채운다. 있으면 존중한다.

**결정적이어야 한다.** 힘 기반 배치는 보통 난수로 시작하는데, 그러면 같은 문서가
매번 다르게 그려진다. **`Math.random`은 코어에서 금지돼 있고**, 그 제약이 여기서는
설계를 옳은 쪽으로 민다 — 계층/격자처럼 결정적인 알고리즘만 쓴다.

**호환성.** 하위호환.

**비용.** 대. 다만 `dag` 계층 배치 하나만 해도 값어치를 한다.

**대안.** 형식이 아니라 **에디터 기능**으로 두는 방법도 있다 — 버튼을 누르면 좌표를
계산해서 문서에 써 넣는다. 그러면 런타임 비용이 0이고 결과가 문서에 남는다.
**이쪽이 더 나을 가능성이 높다.**

## 채택 기준

새 기능을 볼 때 확인할 것.

1. **`frame(t) = f(document, t)`가 유지되는가.** 이게 깨지면 서버 렌더, 필름스트립,
   스크럽, 정적 내보내기가 함께 깨진다. 협상 대상이 아니다.
2. **코어 순수성을 지키는가.** `document`·`window`·`Date.now`·`Math.random` 금지.
   `scripts/check-core-purity.ts`가 강제한다.
3. **383개 기존 문서가 그대로 도는가.** `check:legacy-equivalence`가 확인한다.
4. **에디터가 만들 수 있는가.** 만들 수 없는 기능은 손으로 JSON을 쓰는 소수만 쓴다.
   `code` 요소가 그 증거다.
5. **갤러리에 데모를 넣을 수 있는가.** 넣을 수 없다면 설명할 수 없는 기능이다.
   `tests/gallery-coverage.test.ts`가 강제한다.
